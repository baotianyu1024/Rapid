# Revision experiments: execution and verification

Run commands from the repository root. The `experiments/` and `scripts/` entries are
portable CPU entry points. `revision/benchmarks/` preserves the exact GPU and
baseline drivers used for the revision; some drivers refer to the original
`/tmp/rapid_*` and `/dev/shm/rapid_*` experiment layout. Set up those paths and
the CUDA/Python libraries before running them on another machine. A completed
log from a different layout is not a fresh measurement.

## 0. Environment, sources, and space

Use Python 3.10+, GCC with C++17/OpenMP, PyTorch/TorchRec, CUDA, NCCL, MPI,
HugeCTR, and the framework-specific build dependencies. The CPU setup is:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/build.py --jobs 4
python scripts/smoke_test.py
```

The framework source snapshots are in `revision/frameworks/{HugeCTR,torchrec,HET-GMP,Herald,BagPipe}`.
Their source commits and upstream URLs are recorded in `experiments/dependencies.json`;
build them using their own build instructions. `revision/frameworks/README.md`
records the snapshot scope. HugeCTR is the RAPID GPU substrate; the other four
are comparison implementations. EMBark is exercised through the HugeCTR
training driver, and RAPID's CPS/ACP source is in `cps/` and `acp/`.

All raw data, generated data, model checkpoints, build outputs and logs belong
outside this Git repository. The examples use `DATA_ROOT=/tmp/rapid_revision_data`
and `RUN_ROOT=/tmp/rapid_revision_runs`; select a larger non-home filesystem if
needed. **Before each download, generation, shuffle, split or staging step**, run
`python revision/check_space.py --output PATH --bytes EXPECTED_BYTES`, allowing
headroom for temporary copies. The preprocessing scripts also check capacity
before writing their outputs. Never read earlier files in `store/` as input.

```bash
export DATA_ROOT=/tmp/rapid_revision_data RUN_ROOT=/tmp/rapid_revision_runs
mkdir -p "$DATA_ROOT" "$RUN_ROOT"
python revision/check_space.py --output "$DATA_ROOT" --gib 20
```

## 1. Download, preprocess, shuffle, and split

Fresh Criteo Click Logs shards: `download_criteo_multiday.py` checks available
space for each shard and verifies the source SHA-256. Obtain Kaggle and Taobao
raw files from their official distributions; record their URLs and checksums in
your run manifest. Both Criteo converters shuffle by default; do not pass
`--no_shuffle` to the TSV converter. Its output is 912 bytes per row. Taobao preprocessing also
shuffles by default. Train/eval splitting must occur after shuffling and on a
global batch boundary.

```bash
python revision/benchmarks/download_criteo_multiday.py --out "$DATA_ROOT/criteo_raw" --files-per-day 4
python revision/check_space.py --output "$DATA_ROOT" --gib 4
python experiments/reproduction/scripts/prepare_criteo_parquet.py --files "$DATA_ROOT"/criteo_raw/2015-02-15/*.parquet --output "$DATA_ROOT/criteo_shuffled.bin" --cache "$DATA_ROOT/multihot_lookup" --scope 2015-02-15 --max-rows 1048576 --shuffle-seed 42
python data_preparation/taobao_preprocess.py --raw_dir "$DATA_ROOT/taobao_raw" --output_dir "$DATA_ROOT/taobao" --seed 42
python revision/benchmarks/split_r1_holdout.py --source "$DATA_ROOT/criteo_shuffled.bin" --out "$DATA_ROOT/day6_split" --record-bytes 912
```

Choose the actual downloaded Parquet files from the manifest. If using the
original Criteo TSV instead, run `data_preparation/criteo_singlehot_to_multihot.py`
with `--input`, `--output` and `--shuffle_seed 42`; its shuffle is the default. `split_r1_holdout.py` checks capacity before
its writes. The 8-GPU window uses 983,040 training and 65,536 holdout rows,
local batch 8,192, embedding dim 32 and 510 steps for the 12 real-data/model
comparisons. Record row count, seed and input SHA-256 before planning.

T180/T200/T510 are generated by the official HugeCTR Zipf scripts (one 65,536-row
part, not the full 100-part release). The generator checks disk and RAM before
writing. These cases are used for communication comparison; the full official
model/storage layout did not fit the available V100 memory for comparable
8-GPU end-to-end runs.

```bash
python revision/check_space.py --output "$DATA_ROOT" --gib 8
python revision/benchmarks/generate_official_t_shard.py T180 --out "$DATA_ROOT/T180"
python revision/benchmarks/generate_official_t_shard.py T200 --out "$DATA_ROOT/T200"
python revision/benchmarks/generate_official_t_shard.py T510 --out "$DATA_ROOT/T510"
```

Verify each `manifest.json`: generator hash, row count, table count, file bytes
and data hash. Generator runs need separate fresh output directories.

## 2. Meta review 1: methods, ACP/CPS and external baselines

Run RAPID's full offline CPS, per-table ACP and capacity-balancing pipeline on
the same shuffled binary given to the baselines. For 8 GPUs the input must
contain `8 x 8192 x batches` rows. The final schedule retains every global
batch's samples and fixes ACP once from the profile, before training.

```bash
bash run_all.sh --input "$DATA_ROOT/criteo_shuffled.bin" --dataset criteo --ranks 8 --batch-size 8192 --batches 16 --out "$RUN_ROOT/day6_8"
python experiments/export_runtime_plan.py --help
python experiments/acp/export_hugectr_acp.py --help
python experiments/build_baselines.py --sources revision/frameworks
python experiments/run_baselines.py --case "$RUN_ROOT/day6_8" --methods gmp herald --sources revision/frameworks --epochs 5
```

`communication.json`, `optimized/peak_samples/storage.json` and the ACP plan
give remote embedding receives, memory balance and selected Unique/Reduction
tables. Run `experiments/run_baselines.py --help` for TorchRec and BagPipe
options; those require their PyTorch/FBGEMM environment. The original GPU
drivers are `revision/benchmarks/run_rowwise_d32_e2e.sh` (HugeCTR, RAPID and
TorchRec), `run_r1_embark_d32.py`, `run_het_d32_holdout.sh`,
`run_herald_r1.sh` and `run_remaining_bagpipe_r1.sh`. Stage the corresponding
shuffled, checked inputs with `stage_checked.py` before running them.

```bash
python revision/benchmarks/stage_checked.py "$DATA_ROOT/criteo_shuffled.bin" /dev/shm/rapid_revision/day6.bin
RW_DATASETS='kaggle terabyte taobao' RW_STEPS=510 bash revision/benchmarks/run_rowwise_d32_e2e.sh
python revision/benchmarks/run_r1_embark_d32.py --datasets kaggle terabyte taobao --models dlrm dcnv2 wide_deep deepfm --seeds 42 --steps 510
HET_MODELS='dlrm dcnv2 wide_deep deepfm' bash revision/benchmarks/run_het_d32_holdout.sh
bash revision/benchmarks/run_herald_r1.sh
RAPID_BAGPIPE_DATASET=kaggle RAPID_BAGPIPE_MODEL=dlrm RAPID_BAGPIPE_TRAINERS=8 RAPID_BAGPIPE_STEPS=510 bash revision/benchmarks/probe_bagpipe_taobao.sh
bash revision/benchmarks/run_remaining_bagpipe_r1.sh
python revision/benchmarks/summarize_rowwise_d32_e2e.py
python revision/benchmarks/summarize_r1_embark_d32.py
python revision/benchmarks/summarize_het_d32_holdout.py
python revision/benchmarks/summarize_herald_r1.py
python revision/benchmarks/summarize_bagpipe_r1.py
python revision/benchmarks/summarize_paper_table1_20261110.py
```

The last two scripts read the original driver output paths. Before using the
GPU shell script, inspect its first 35 lines and map `root`, `split`, `plan`,
`out_root`, Python executable, HugeCTR build libraries and NCCL library to
your environment. Run each framework's companion driver after the same input
mapping; the summaries reject missing or incomplete runs. HET-GMP uses its
native shared-table SGD 0.01 path; the other GPU methods use AdaGrad 0.01.

## 3. Meta review 2(a,b): measured 8 GPUs, broader workloads, traffic

`run_rowwise_d32_e2e.sh` trains DLRM, DLRM-DCNv2, Wide&Deep and DeepFM on
Kaggle, Terabyte and Taobao. TorchRec is forced to Row-wise for the embedding
comparison. The GPU training window includes mapping, scheduling and framework
communication, and excludes offline planning, input preparation, initialization
and validation. The original machine disabled NCCL P2P and IB for its PCIe
comparison. Stage each complete input in RAM and use the input diagnostic
scripts to check that reading does not dominate training.

```bash
bash revision/benchmarks/run_rowwise_d32_input_probe.sh
bash revision/benchmarks/run_het_input_diagnostics.sh
python revision/benchmarks/summarize_het_input.py
python revision/benchmarks/run_tseries_d32_offline.py t180 --manifest "$DATA_ROOT/T180/manifest.json" --out "$RUN_ROOT/t180"
python revision/benchmarks/run_tseries_d32_offline.py t200 --manifest "$DATA_ROOT/T200/manifest.json" --out "$RUN_ROOT/t200"
python revision/benchmarks/run_tseries_d32_offline.py t510 --manifest "$DATA_ROOT/T510/manifest.json" --out "$RUN_ROOT/t510"
python revision/benchmarks/compare_tseries_comm_d32.py
```

The T-series comparator has original `/tmp` defaults; change its input and
output roots to your fresh manifests before execution. Compare all baseline traffic using `experiments/run_baselines.py`
on the same case and report **forward remote receives** in vectors or bytes,
with dim 32. `compare_tseries_comm_d32.py` preserves the original count used
for the HugeCTR/RAPID check; it is not a seven-framework GPU network trace.
For 16-128 logical ranks use `run_all.sh --ranks 64` and label it a CPU
protocol replay, separate from measured 8-GPU throughput.

## 4. Meta review 2(c): batch, parameters, order and memory

Re-run the same input and sample count with each batch size. Compute a new
all-Unique comparator for every size; changing batch size changes deduplication
opportunity. `launch_sensitivity.py` is the original case matrix for beta,
gamma, hot Top-K and reversed/profile seed order, but its historic toolchain
paths need adjustment. Results are summarized by `report_sensitivity.py`.

```bash
python experiments/archive/revision_v3/launch_sensitivity.py
python experiments/archive/revision_v3/report_sensitivity.py
python experiments/archive/revision_v3/audit_storage.py --help
```

Use `communication.json` and `storage.json` from each case to verify remote
receives and maximum/mean primary embedding storage. `run_all.sh` can be
repeated with `--batch-size 512`, `1024`, `2048`, `4096`, `8192` and `16384`;
adjust `--batches` so the same rows are counted, and use a fresh output
directory each time. Original sensitivity artifacts are not checked into Git.

## 5. Meta review 2(d): drift and zero migration

The incremental planner adds new IDs and schedules new samples while keeping
old owner and physical IDs fixed. Compare frozen placement, incremental
updates and a full rebuild on matching samples. `summary.json` verifies zero
old-ID migration; the full rebuild is a communication reference and would
also require embedding weights plus optimizer-state migration in training.

```bash
python experiments/run_incremental.py --input "$DATA_ROOT/criteo_shuffled.bin" --out "$RUN_ROOT/incremental" --ranks 8 --batch-size 8192 --initial-batches 32 --window-batches 1 --windows 32
python revision/benchmarks/measure_incremental_vs_rebuild.py --input "$DATA_ROOT/criteo_shuffled.bin" --out "$RUN_ROOT/rebuild_compare" --local-batch 2048
```

The second historical driver uses a compiled sample-group library; build the
`experiments/reproduction/rapid_peak_optimization` extensions before execution. Check
its JSON for equal input windows, old owner/physical changes of zero, remote
receive counts and full-rebuild migration counts.

## 6. Reviewer checks: MCR, Figure 4, accuracy and AUC

The MCR test considers all cold IDs in 2,097,152 multi-hot Criteo rows. For
minimum support 10/20/50/100, it reports how many cold IDs have high maximum
co-occurrence; the support threshold removes IDs seen too few times to make
the ratio informative. Figure 4's Reduction count is one vector per sample
and nonempty remote owner for that table.

```bash
python revision/check_space.py --output "$DATA_ROOT" --gib 6
python experiments/reproduction/scripts/prepare_criteo_parquet.py --files "$DATA_ROOT"/criteo_raw/2015-02-15/*.parquet --output "$DATA_ROOT/criteo_mcr_shuffled.bin" --cache "$DATA_ROOT/multihot_lookup" --scope mcr --max-rows 2097152 --shuffle-seed 42
bash experiments/run_mcr.sh "$DATA_ROOT/criteo_mcr_shuffled.bin" "$RUN_ROOT/mcr"
python experiments/reproduction/scripts/measure_figure4.py --input "$DATA_ROOT/criteo_shuffled.bin" --output "$RUN_ROOT/figure4.json" --batches 20
python experiments/reproduction/scripts/test_figure4.py
python revision/benchmarks/run_r5_paired_d32.py --datasets kaggle terabyte taobao --models dlrm dcnv2 wide_deep deepfm --seeds 41 42 43 44 45 --steps 510
python revision/benchmarks/summarize_r5_paired_d32.py
```

The AUC driver computes paired reference/RAPID runs on identical train and
holdout splits; verify the run JSON, paired AUC difference and LogLoss before
reporting. It expects the original RAM and plan paths, CUDA libraries and
Python environment. The longer convergence drivers are
`run_multiday_extension.sh` and `summarize_multiday_convergence.py`.

## Reproduction boundaries

GPU drivers preserve the experiment machine's paths, build layout and
software versions. Update those paths explicitly on a new machine and record
the changes. A `--help` or syntax check proves only that a driver parses; it
does not regenerate the reported training measurements. The full official
T-series models were not completed as comparable 8-GPU end-to-end runs;
their communication results use the official single-part generated inputs.
No dataset, historical output, credential or prebuilt framework binary is
included in this source branch.
