# Revision of VLDB Submission #1058

感谢各位审稿人的建议。以下先报告共同关注的修订结果，再逐条回答具体意见。

## 实验设置

端到端实验采用 8 卡 32 GiB V100、每卡 batch 8,192、预打乱的内存输入和 510 步 GPU 训练窗口，计入训练时映射与通信。RAPID 优化 Row-wise 分片，TorchRec 对照也采用全 Row-wise。HET-GMP 的共享表使用 SGD 0.01（表 1 中标注的 Kaggle／DCN 例外），其余方法使用 AdaGrad 0.01。T 系列通信和精度实验的配置见对应段落。

## Meta Revision 2：物理扩展性的边界

我们同意审稿人关于物理扩展性的意见：目前没有完成多机或 16–128 GPU 的端到端训练实验。论文中 16–128 rank 的结果只来自访问记录上的通信与负载计数，不能证明大规模部署的实际吞吐或加速。我们将收紧摘要、Section 7.6 和结论中的表述：训练加速只对应已实测的单机 8 卡；更大规模仅报告逻辑 rank 的通信趋势，并将多机物理扩展性列为尚未验证的限制。

## Meta Revision 3：离线计划与增量更新

审稿人关心离线计划在数据增长后是否仍有效，以及更新是否需要搬迁已有 embedding。我们在已打乱的 Criteo day6 multi-hot 输入上，从 2,097,152 条初始样本建立计划，再依次加入 56 个互不重叠、每个 65,536 条样本的窗口。增量路径只放置新 ID、调度新增样本；已存在 ID 的 owner 与 physical ID 保持不变，因此本实验没有旧 embedding 的迁移量。表中四种策略在同一批新增窗口上的比较显示，增量通信较纯 Unique 减少约 74%，并接近每轮全量重算。

下表比较四种策略：纯 Unique 使用哈希放置；“不更新放置”沿用原计划，仅轮流分配新 ID；增量更新按新 ID 的访问关系补充放置；全量重算重新规划全部已见数据。每格为 W49–W56 平均每 rank、每步**前向远端接收**向量数。

| 策略 | 放置方式 | 接收向量／rank／步 | 相对纯 Unique 减少 |
| --- | --- | ---: | ---: |
| 纯 Unique（W49–W56） | 原分配与哈希放置 | 480,344.75 | — |
| 不更新放置 | 新 ID 轮流放置 | 178,368.19 | 62.87% |
| RAPID 增量更新 | 新 ID 按访问关系放置 | 125,080.08 | 73.96% |
| 全量重算 | 每轮重做全局计划 | 103,956.46 | 78.36% |

在同一批样本上，增量更新比不更新放置进一步减少 29.88% 的远端接收量；它比全量重算多 20.32%，但无需搬迁旧 embedding。

## Meta Revision 4：batch size、负载与参数敏感性

增大 batch size 会增加批内重复 ID 的去重机会，并进一步扩大 RAPID 相对全 Unique 的通信优势。为检验这一点，我们在同一份 262,144 条 Criteo 输入上固定 8 个 rank，分别以六档每卡 batch size 运行 RAPID；每档都用相同的样本和分批方式重新计算全 Unique 基线。表 2 将各档的前向远端接收向量总数除以处理的样本数，避免因 batch 数不同而混淆通信量比较。这份输入与前述增量实验的 W49–W56 不同，因此两表的全 Unique 数值不必逐值相等。

**表 2　Batch size 消融**

| 每卡 batch | 全 Unique（向量／样本） | RAPID（向量／样本） | RAPID 减少 |
| ---: | ---: | ---: | ---: |
| 512 | 90.250 | 20.485 | 77.30% |
| 1,024 | 82.145 | 17.070 | 79.22% |
| 2,048 | 74.045 | 13.170 | 82.21% |
| 4,096 | 66.145 | 10.380 | 84.31% |
| 8,192 | 58.540 | 7.960 | 86.40% |
| 16,384 | 51.230 | 5.965 | 88.36% |

随着每卡 batch 从 512 增至 16,384，RAPID 的远端接收量从 20.485 降至 5.965 向量／样本，相对同档全 Unique 的减少比例从 77.30% 升至 88.36%。更大的 batch 让更多重复 ID 落在同一批次内，按批去重后两种方法的单位样本通信量都下降，而 RAPID 的优势继续扩大。

审稿人还担心最忙 rank 的负载抵消平均通信收益。我们逐步统计最忙 rank 的前向接收量：在三组真实数据上，它是各 rank 平均量的 1.030–1.197 倍，未出现极端通信集中。

## Meta Revision 5：共现统计与精度

审稿人指出，只出现一两次的冷 ID 很容易得到很高的共现比例。我们对论文使用的 Criteo multi-hot 工作负载取 2,097,152 条样本，先按样本统计每个 ID 的出现次数，同一样本内重复出现只计一次。出现频率低于 0.01%（即少于 210 个样本）的 ID 定义为冷 ID。对每个冷 ID，找出与它共同出现在同一样本中次数最多的另一个冷 ID，再用该共同出现次数除以目标 ID 的出现次数，得到 MCR。

表 3 的“目标 ID 至少出现”用于排除证据太少的目标：例如阈值 100 只统计出现 100–209 次的冷 ID；若目标出现 100 次、某个冷伙伴与它同现 96 次，则 MCR=96%。伙伴仍可为任意其他冷 ID。每一档均枚举所有符合条件的目标 ID，而不是抽样。阈值从 10 提高到 100 后，MCR>95% 的比例未下降，说明这一现象在论文的 multi-hot 工作负载中不只来自出现一两次的 ID。

**表 3　MCR>95% 的冷 ID**

| 目标 ID 至少出现（样本数） | 符合条件的冷 ID | MCR>95% 的冷 ID | 比例 |
| ---: | ---: | ---: | ---: |
| 10 | 1,886,103 | 1,333,054 | 70.68% |
| 20 | 953,848 | 770,892 | 80.82% |
| 50 | 353,257 | 299,515 | 84.79% |
| 100 | 129,222 | 110,490 | 85.50% |
