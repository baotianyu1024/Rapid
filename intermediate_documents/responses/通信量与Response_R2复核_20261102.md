# 通信量与 Response R2 复核（2026-11-02）

## 结论

本次全范围 shuffle 输入上的 RAPID、HET-GMP、TorchRec 三组数据，**通信排名和趋势与 `中文Response.md` 表 R2 一致**：Kaggle、Terabyte 为 RAPID < HET-GMP < TorchRec；Taobao 为 HET-GMP < RAPID < TorchRec。九项中有七项相对差距不超过 0.6%，Terabyte 的 RAPID、HET-GMP 分别低 2.88%、2.98%；因此不能说 R2 已逐值复现。这里的“接近”是同数量级及趋势一致，不是相同实验输入的误差界。

## 统一口径与复算方法

- 8 个逻辑 rank、每 rank batch 8192、1,048,576 行、5 epoch、FP32 embedding 维度 128；统计全 rank 前向和反向跨端 embedding payload，单位 GiB（2^30 字节），排除 ID、metadata、dense 梯度和物理 NCCL 协议开销。这是 CPU trace/协议计数，**不是 GPU 网络实测字节**。
- RAPID 使用本次最终 CPS/owner/sample 优化后的静态 ACP 选择。`final_optimized_traffic.json` 的 `acp_vectors` 是每 rank、每个完整 global batch 的前向均值；按远端发送与接收总数相等，将其乘以 8 rank、16 batch/epoch、5 epoch、前反向 2、每向量 512 字节。Kaggle 表 20 选择 Reduction（其 Unique 候选 67,717.95，高于 57,344 阈值）；Terabyte 26 表均选 Unique；Taobao 4 表均选 Unique。
- HET-GMP 用原生分区器进行 10 轮分区和 1% 镜像排序，随后对全部样本回放 5 epoch，取 `vector_bytes_128 + hypothetical_final_flush_vector_bytes_128`。三组回放的 `pending_updates` 均为 0。GMP 的样本分配使每 epoch 有 17 个 step，第 17 步为不满 batch；回放仍统计其真实请求，不能把前向每批均值简单乘 16。
- TorchRec 使用安装的 1.1.0 planner，在 dim=128、16 GiB HBM、14.66833055 GiB/s host 带宽下对本次活跃词表重新规划，再以 `table_bytes` 计 80 个完整 step 的前反向 payload。Kaggle 规划为 23 个 data-parallel、2 个 table-wise、1 个 row-wise；Terabyte 为 18/7/1；Taobao 为 4 个 table-wise。此规划与本次 Criteo GPU 吞吐实验的 dim=32 规划不同，不能将本表称为 GPU 实际链路测量。

输入与结果：`/tmp/rapid_shuffle2026_{kaggle,terabyte}/data`、`/tmp/rapid_fresh_stage/taobao_8_v2/data`、`/tmp/rapid_shuffle2026_results/{kaggle,terabyte,taobao}/final_optimized_traffic.json`、`/tmp/rapid_response_recheck2026/{kaggle,terabyte,taobao}_gmp/het_gmp_s0.json`、`/tmp/rapid_response_recheck2026/{kaggle,terabyte,taobao}_torchrec_dim128_plan.json`。Kaggle 从 45,840,617 行全范围均匀抽样；Terabyte 从重新下载的 8 个 Parquet 分片共 6,884,005 行均匀抽样；Taobao 全量 shuffle 后截取子集。同名数据集不代表与 Response 使用同一组行、同一分区或同一离线计划；Terabyte 的约 3% 差异不能归咎于测量噪声，也不能据此判定 Response 原数字错误。

## 尚不能对照的项目

本轮没有在新 shuffle 输入上重跑 Herald、BagPipe 与 T180/T200/T510 的 R2 通信；不能对它们声称已复现。Response 的 R1 端到端吞吐表仍是待填项，本次 GPU 稳态吞吐仅能作为另一个实验结果，不能与 R1 数字逐项对照。前一份 `全量Shuffle与三框架公平性复测报告.md` 的通信表是**每卡每批前向**，Criteo 训练维度为 32；拿其数字与这里的 R2 全 rank、5 epoch、前反向、128 维 GiB 直接比较，会产生错误结论。实验使用内存驻留输入，已记录测量窗口的进程/rank `read_bytes` 增量为零；这支持当前实验没有物理磁盘读取瓶颈，但不证明冷盘训练的输入路径也无瓶颈。
