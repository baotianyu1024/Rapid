## 本回复通用的实验设置

训练实测使用单机 8 张 32 GiB V100；除非另有说明，每卡 batch 为 8,192。输入预先打乱并驻留主机内存；吞吐统计 510 步 GPU 训练窗口，包含在线映射与通信，不包含离线规划、输入准备、初始化和验证。RAPID 针对 Row-wise embedding 分片优化，因此 TorchRec 采用全 Row-wise 对照。HugeCTR、TorchRec、EMBark、Herald、BagPipe 与 RAPID 使用 AdaGrad 0.01；HET-GMP 的共享表使用其原生 SGD 0.01，标注的 Kaggle/DCN 运行例外。投稿论文原本使用 8 张 16 GiB PCIe V100；当前 32 GiB 机器上的结果是新增实测，不能称为相同硬件的逐值复现。

**拟写入论文的位置：Section 7.1，“Hardware and Training Configuration”现有硬件段落之后。**

> 修订实验另外使用单机 8 张 32 GiB V100。除非另有说明，每 rank 每步处理 8,192 条样本。输入在训练前打乱并预载入内存。报告的吞吐统计 510 步 GPU 训练，包括在线 ID 映射、调度和通信，不包括一次性预处理、初始化和验证。RAPID 优化 Row-wise embedding 放置，因此 TorchRec 对照使用 Row-wise 分片方案。HET-GMP 的共享表使用原生 SGD、学习率 0.01；其他系统使用 AdaGrad、学习率 0.01，结果表中注明例外。

## Meta Revision 3：离线计划与增量更新

**回复。** 我们测试数据持续追加时能否扩展原计划。先从 2,097,152 条预打乱的 Criteo day-6 multi-hot 样本建立初始计划，再依次加入 56 个互不重叠、每个 65,536 条样本的窗口；四种方法都在**同一批**最后八个窗口 W49–W56 上比较。RAPID 只放置新 ID、调度新增样本；旧行的 owner 和 physical ID 不变，旧行迁移计数为零。增量更新相对哈希放置的全 Unique 将前向远端接收量减少 73.96%，相对保留旧计划且轮流放新 ID 的方案再减少 29.88%。全量重算的通信量更低，但它改变已有计划。这一同日打乱数据的追加实验不代表真实时间漂移，也没有计量规划和分发所需时间。

## Meta Revision 5：冷 ID 共现与精度

**回复。** 我们回应“高共现比是否只因 ID 出现一两次”的疑问。在 2,097,152 条 Criteo **multi-hot** 样本上，出现于不到 0.01% 样本（少于 210 条）的 ID 定义为冷 ID。支持次数是包含某 ID 的不同样本数，同一条样本内重复出现只算一次。对每个目标冷 ID，MCR 等于它与任一其他冷 ID 的最大共同出现次数除以目标支持次数。最低支持次数为 100 时，只保留出现 100–209 次的冷目标；其中 85.50% 的 MCR 仍大于 95%。这是特定工作负载统计：multi-hot 扩展本身可能产生确定性共现，因此不能将这个比例直接推广到未扩展的类别数据或未来时间窗口。

**表 R7：所测 multi-hot 负载中 MCR>95% 的冷 ID。**

| 目标最低支持次数 | 合格冷 ID 数 | MCR>95% 的 ID 数 | 比例 |
| ---: | ---: | ---: | ---: |
| 10 | 1,886,103 | 1,333,054 | 70.68% |
| 20 | 953,848 | 770,892 | 80.82% |
| 50 | 353,257 | 299,515 | 84.79% |
| 100 | 129,222 | 110,490 | 85.50% |

RAPID 保持每个原始 global batch 的样本集合，只改变样本分配到哪个 rank。在样本计算不依赖 rank 且优化器更新语义相同的前提下，batch 目标与全局梯度在数学上不变，浮点归约顺序除外；这一论证不保证 rank 局部状态或随机算子下逐位一致。完整 Taobao/DLRM 一轮训练使用 23,920,640 条训练、2,621,440 条验证样本，三个配对种子下 HugeCTR 与 RAPID 的平均 AUC 为 0.657161 和 0.657166。配对平均差（RAPID 减 HugeCTR）为 +0.000004，95% 置信区间 [−0.000215, +0.000223]。区间包含零，但不等于证明两者等效。
