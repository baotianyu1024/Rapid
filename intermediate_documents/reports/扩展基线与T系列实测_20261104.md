# 扩展基线与 T 系列实测（2026-11-04）

## 口径

本轮范围为 Criteo Terabyte、Criteo Kaggle、Taobao，以及 HugeCTR 官方生成器的 T180、T200、T510。MovieLens 不参与本轮实验。机器为 8 张 V100 32 GiB；主实验 local batch=8192、embedding dim=32，T 系列单分片 local batch=512、dim=32。设置 `NCCL_P2P_DISABLE=1` 和 `NCCL_IB_DISABLE=1`。真实数据采用固定 shuffle 后的 1,048,576 行子集，训练 510 步并在 65,536 行留出集上计算 AUC；训练窗口与进程初始化分开计时。以下数值是**单次短训**，不能代替 Response R1/R5 所需的三次独立完整收敛及精度配对。各框架的模型实现和初始 embedding 仍未完全配对，AUC 不能据此断言算法精度等价。

## 官方 T 系列单分片 GPU 训练

完整官方 benchmark 包含 100 个分片，当前只训练第 0 分片的活跃 ID 工作集，重复至 510 步；不能称为完整官方词表的端到端结果。吞吐为千 samples/s；原始训练日志见 [GPU CSV](tseries_d32_gpu_training_20261104.csv)。合成标签不用于 AUC 解释。

| 负载 | TorchRec 全 Row-wise | HugeCTR | RAPID |
| --- | ---: | ---: | ---: |
| T180 | 34.826 | 40.774（hash ACP：77 Reduction、100 Unique） | 4.726 |
| T200 | 37.677 | 44.563（全 Unique） | 21.283 |
| T510 | 16.826 | 26.332（全 Unique） | 19.056 |

TorchRec 的训练窗口进程读取字节为零。HugeCTR T200/T510 为零，T180 约 1.48 MB，远小于训练数据总量；RAPID T180 首次从 `/tmp` 读取产生约 2.89 GB 物理读取，因此该次 10 步探针不能作无读取瓶颈吞吐。正式 510 步改用经 SHA 核对的 `/dev/shm` 副本，训练窗口 `read_bytes=0`，但仍耗时 **442.010 秒**，说明该负载的在线映射或通信/计算路径仍有显著开销，不能用其较小的回放 payload 预测吞吐。T180 全 Unique 在 `model.compile()` 显存不足，改测 hash ACP，不能将其当作同策略比较。HET-GMP T200/T510 即使关闭镜像缓存仍在初始化时 CUDA OOM。完整官方词表仅权重、梯度和 AdaGrad 状态的理想均分下界分别为 T180 **50.56 GiB/卡**、T200 **37.17 GiB/卡**、T510 **40.01 GiB/卡**，超过 32 GiB/卡。

T510 RAPID 的首轮 510 步与两个长时 CPU 回放重叠，耗时 137.756 秒；暂停回放后的隔离重测耗时 **109.621 秒**，对应表中 19.056 千 samples/s，训练窗口 `read_bytes=0`。T200 RAPID 同样在 CPU 回放暂停期间完成，耗时 **98.153 秒**。隔离重测仍比 HugeCTR 全 Unique 慢，不能仅凭 RAPID 的通信 payload 较低就推断端到端必然更快；该差异还需要同输入内核与在线映射的时间线分解。

BagPipe 需要 oracle、embedding server 和 8 个 trainer 的 RPC GPU 训练适配；Herald 当前完成的是 LAIA 内核回放。这两者没有当前配置下的 GPU 吞吐或 AUC，其空白不能用 CPU 协议回放填充。EMBark 的官方自动分片规划器位于 HugeCTR `benchmarks/embedding_collection/hugectr/sharding`，现已接入本地同模型 HugeCTR GPU 训练入口；三个真实数据集各四模型的 12 次、510 步 GPU 测量均完成，详见 [EMBark CSV](embark_d32_e2e_results_20261104.csv)。官方默认 `dp_threshold=0`、`dense_threshold=0`，每卡 embedding 预算设为 20 GiB；所得计划在 Criteo 的 26 表与 Taobao 的 4 表上均为全 Reduction，训练窗口 `read_bytes=0`。这些是官方规划器加当前统一模型训练入口的适配结果，并非上游未修改脚本的原始 benchmark。
