# 增量更新与全量重建：旧行搬迁及回本点

本文件保留完整实验记录；审稿回复仅采用零旧行迁移及通信收益接近全量重算的结论，不报告回本步数。

## 实验口径

使用重新下载的 Criteo day6 multi-hot 输入 `/tmp/rapid_fresh_stage/day6_5767168.bin`，取不重叠的前 32,768 条样本建立初始计划，再加入后续 16,384 条样本。8 个逻辑 rank，每卡 batch 2,048，embedding dim 32。两条路径使用相同规划算法和输入顺序：增量路径仅为新 ID 分配位置并调度新样本；全量路径对累计 49,152 条样本从空状态重新规划。后续窗口的通信均按全 Unique、前向从其他 rank 接收的 embedding 向量数计量。两个路径都保持原 global batch 的样本集合。

此处测量的是同一天内的样本增长；后文另测跨日期输入。规划时间为机器空闲时两次 CPU 实测的中位数；PCIe 路由时间为三次独立 NCCL 测量的中位数。通信量由完整样本与 owner 映射逐表计数。旧行搬迁量包含 FP32 embedding 权重与 AdaGrad 累加器，单行 256 字节。代码：`code/measure_incremental_vs_rebuild.py`；无干扰规划结果：`/tmp/rapid_remap_sameday_repeat1_20261113/result.json` 和 `/tmp/rapid_remap_sameday_repeat2_20261113/result.json`。

## 结果

| 指标 | 保留旧行的增量更新 | 全量重建并迁移 |
| --- | ---: | ---: |
| 本次规划时间，两次中位数 | 8.122 s | 12.718 s |
| 旧行跨 GPU 改变 owner | 0 | 134,665 行 |
| 旧行在原 GPU 改变 physical ID | 0 | 1,527,492 行 |
| 旧权重与 AdaGrad 状态跨卡传输 | 0 | 34.47 MB |
| 旧权重与 AdaGrad 状态同卡重排 | 0 | 391.04 MB |
| 新窗口每全局步前向远端接收 | 199,509 向量 | 177,164 向量 |

全量重建使新窗口的前向远端接收量再下降 22,345 向量／步，即 11.20%。但它多花约 4.596 秒规划时间，并需要旧行跨卡搬迁及同卡重排。增量更新完全保留旧行 owner 和 physical ID；这不等于零更新成本，其新 ID 分配和新样本调度已计入 8.122 秒。

PCIe 配置的八卡 NCCL microbenchmark 按旧行真实 owner 对发送：旧权重及 AdaGrad 状态跨卡传输中位数 1.063 ms；同卡旧行随机重排中位数 0.363 ms。按后续样本的实际 owner 路由执行前向与反向 all-to-all，重建每步比增量节省的中位数为 0.151 ms。规划时间差加搬运时间约 4,597 ms，因此 **在这一组输入下，全量重建估计约需 30,500 个后续全局步才回本**。

这是基于精确路由计数、独立 NCCL 传输测量与 CPU 规划计时的回本估计，假设后续步继续呈现相同的通信差；尚未包含元数据发布、训练计算与通信重叠。仅按迁移字节与节省的双向 embedding payload 相比，忽略规划及同卡重排，得到 7 步的流量等价下界，它不是端到端时间回本点。三次传输原始记录：`/tmp/rapid_remap_sameday_repeat1_20261113/transport_run1.json` 至 `transport_run3.json`；测试代码：`code/benchmark_remap_transport.py`。

跨日期的初次单次规划测量与 HET-GMP 作业重叠，放大了规划时间差；报告与回复统一采用 GPU 和 CPU 空闲后的两次规划复测。放置方案、迁移行数与远端向量数在重复运行中完全相同。

## 跨日期输入复核

另取 Criteo 2015-02-15 至 17 日训练数据中的 32,768 条样本建初始计划，再加入独立的 2015-02-18 数据 16,384 条。两条路径复用上面的 batch、维度和全 Unique 协议；新旧样本来自不同日期，因而这一组检查真实日期变化下的放置取舍。无干扰规划结果在 `/tmp/rapid_remap_drift_repeat_20261113/result.json` 和 `/tmp/rapid_remap_drift_repeat2_20261113/result.json`。

| 指标 | 保留旧行的增量更新 | 全量重建并迁移 |
| --- | ---: | ---: |
| 本次规划时间，两次中位数 | 7.416 s | 12.053 s |
| 旧行跨 GPU 改变 owner | 0 | 137,519 行 |
| 旧行在原 GPU 改变 physical ID | 0 | 1,484,443 行 |
| 旧权重与 AdaGrad 状态跨卡传输 | 0 | 35.20 MB |
| 旧权重与 AdaGrad 状态同卡重排 | 0 | 380.02 MB |
| 新窗口每全局步前向远端接收 | 196,333 向量 | 177,699 向量 |

跨日期窗口新增 619,728 个旧窗口未见的 ID，其 FP32 权重和 AdaGrad 状态合计约 151.3 MiB；增量规划时间已计新 ID 的放置，但两条路径实际的 GPU 新行分配未计。全量重建每步少接收 18,634 个远端向量（9.49%），但比增量多花约 4.638 秒规划时间；增量仍无需搬迁任何旧行。八卡 PCIe NCCL 按跨日期实测路由计时：跨卡迁移中位数 1.089 ms，同卡重排中位数 0.352 ms；重建每步比增量节省的中位数为 0.166 ms。加上规划时间差，**全量重建估计约需 28,000 个后续全局步才回本**。这是独立路由传输与规划计时的估计，尚未包含训练计算及通信重叠。三次传输原始记录：`/tmp/rapid_remap_drift_repeat_20261113/transport_run1.json` 至 `transport_run3.json`。
