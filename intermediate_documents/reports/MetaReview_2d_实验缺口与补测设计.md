# Meta-review 2(d)：现有证据与补测设计

Meta-review 2(d) 要求验证离线计划在 workload drift 下是否仍有效，并计入更新、重映射成本。对应 Reviewer 2 的 W3、D3、R3：用较早窗口建计划，在不重叠的较晚窗口测局部性、通信和吞吐；比较不更新、增量更新与全量重算；记录何时需要更新、旧 embedding 迁移或重编码、新 ID 映射及恢复到目标性能所需的时间。

## 现有证据

当前回复的表 6 在打乱的 Criteo day-6 同源数据上，用 2,097,152 条样本建初始计划，再追加 56 个各 65,536 条样本的窗口，并在相同的 W49–W56 上比较四种策略。RAPID 增量更新的前向远端接收量为每 rank 每步 125,080.08 个向量，较保留旧计划的 178,368.19 少 29.88%；已有 embedding 行的 owner 和 physical ID 变化为零。该结果说明同源数据增长时的通信收益和旧行零迁移。

这还不足以完整回答 2(d)：预先打乱的同一天数据不能代表随时间改变的 ID 热度、共现结构或样本分布。现有表格也没有更新触发频率、规划和计划分发耗时、新 ID 重映射成本、训练暂停时间、后续窗口吞吐或性能恢复时间。旧行零迁移不等于总更新成本为零。

## 最小补测

1. 按真实日期或时间顺序切分 Criteo：较早一天建计划，后续不同日期作互不重叠的执行窗口；不可跨日期打乱后再切分。保留一组同日非重叠窗口作稳定分布对照。
2. 对每个后续窗口，以相同样本和配置比较固定旧计划、RAPID 增量更新、全量重算，以及哈希全 Unique。逐窗口记录本地命中率、前向远端接收量、最忙 rank、八卡训练吞吐，并画出随时间的曲线。
3. 设定并公开更新触发规则，例如远端接收量较初始窗口上升达到预设比例；报告每个阈值的触发次数、两次更新间的窗口数，以及更新前后通信和吞吐。阈值应先固定，再在不同日期测试。
4. 分项计时：新 ID 发现、owner/physical-ID 分配、样本重排、计划生成与序列化、分发、GPU 侧装载及训练暂停。分别统计新行创建、旧行迁移、重编码的行数和字节数，包含优化器状态；报告从触发到恢复至全量重算性能附近的时间。

完成这些测量后，才能对 2(d) 作出“时间漂移下稳健、更新成本可摊销”的完整结论。当前审稿人回复明确保留这一边界，不把表 6 的同日追加实验写成时间漂移实验。
